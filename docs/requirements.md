# sshDesktop 需求讨论记录

本文件按轮次记录需求讨论中已确认的结论和待确认事项，是设计文档（`docs/design.md`，待撰写）的输入。

## 项目一句话

结合 1Panel 面板、哪吒探针等开源项目的实用功能，提供 Web 后台；可在后台开启"桌面模式"，在浏览器里渲染一个类似 Windows / macOS 的桌面，让用户用操作 PC 的方式操作 Linux 服务器。

## 第一轮：定位与架构（2026-10-20）

| 议题 | 结论 |
| --- | --- |
| 管理方式 | 中心面板 + agent 与纯 SSH 免安装两种接入方式结合。每台服务器上都可能同时装有 agent 和面板，agent 必须通用：一个 agent 可被多个面板调用，不重复安装 |
| "桌面"含义 | 网页模拟的桌面（任务栏、开始菜单、可拖拽窗口，窗口内是 Web 应用）。不做 VNC/RDP 真远程图形桌面 |
| 使用者与规模 | 自用或小团队，约 5 台服务器；账号区分管理员和普通用户 |
| 桌面模式与后台 | 同一套功能的两种外观（传统侧边栏后台 / 窗口化桌面），可随时切换；功能模块只实现一次 |
| 技术栈 | 后端 Go；前端 Vue 3 + TypeScript |

## 第二轮：连接、权限与功能分级（2026-10-20）

| 议题 | 结论 |
| --- | --- |
| 内网 / 无公网 IP 服务器 | 没有，不需要"agent 主动连回面板"的反向连接模式 |
| 多面板共用 agent 的权限 | 安装在本机的面板拥有全部权限；其他面板只获得监控等低风险权限 |
| 用户权限模型 | 按功能分配（例如普通用户只能看监控、管文件，不能开终端、改防火墙） |

### 功能分级

- **P0（首版）**：监控概览（CPU、内存、磁盘、网络，实时与历史曲线）、文件管理器（上传下载、在线编辑、压缩解压、权限）、多窗口终端、进程与系统服务管理、Docker 容器与 Compose、计划任务、账号权限、操作审计日志、服务监控（HTTP / TCP / Ping / SSL 证书到期）、防火墙与 SSH 设置、网站管理（Nginx 反向代理 + 自动证书）、应用商店（基于 Docker 一键安装）、备份恢复（含云存储）、按月流量统计、多服务器批量执行命令
- **P1**：安全工具（Fail2ban 等）、AI 助手
- **P2**：告警通知（Telegram、邮件、Webhook、企业微信等）、数据库管理（MySQL / PostgreSQL / Redis）、公开状态页、DDNS

## 第三轮：职责划分与桌面（2026-10-20）

### 面板、agent 与 SSH 的职责划分

| 角色 | 职责 |
| --- | --- |
| 面板 | 负责本机的全部高权限操作（相当于 1Panel 的角色）；桌面模式只管本机 |
| agent | 只做监控等只读的轻量功能，可被任意多个面板读取，无安全风险；装有面板的服务器自带 agent 能力，无需另装 |
| SSH | 中心面板通过 SSH 对其他服务器做轻量操作：监控、文件（SFTP）、终端、批量下发命令；权限即所用 SSH 账号的权限 |

这一划分取代了第二轮"由 agent 区分本机面板与其他面板权限"的设想：agent 本身只读，不再需要区分来访面板。

### 桌面

| 议题 | 结论 |
| --- | --- |
| 多服务器呈现 | 桌面只管本机；其他服务器只涉及监控、文件操作、批量指令等轻量功能。拟在"此电脑"中以类似 Windows "网络位置"的方式呈现其他服务器 |
| 外观风格 | 先做 Windows 11 风格，以后再考虑 macOS 风格切换 |
| 桌面状态 | 记住打开的窗口、位置、壁纸等，保存在服务器上，换设备登录一致 |
| 移动端 | 桌面模式只面向电脑浏览器；手机打开时自动切到后台外观 |
| 交互 | 全部采纳：服务器间拖拽复制文件、双击文本文件用编辑器打开、右键菜单（新建、解压、在此处打开终端）、桌面小组件（CPU、网速）、Ctrl+C/V 复制粘贴文件、回收站、终端分屏与多服务器同步输入 |

- 第四轮（安全与登录）：面板访问方式与域名、登录与两步验证、普通用户对应的 Linux 身份、危险操作确认、面板进程运行身份
